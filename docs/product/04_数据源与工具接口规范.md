# 04 · 数据源与工具接口规范（中国大陆可用）

> 本文档定义 成竹 所有对外数据获取工具。**硬性约束：所有数据源必须在中国大陆无代理直连可用**，禁止使用 Google Search、Twitter/X API、Reddit API、境外 SaaS（含 Zep Cloud）。
> 执行 Agent 实现时：每个工具做成独立 Python 模块，放在 `backend/app/tools/` 下，统一返回本文档第 1 节定义的 `EvidenceCard` 结构。

---

## 1. 统一返回结构：EvidenceCard

所有采集工具的返回值必须是 `list[EvidenceCard]`。定义（`backend/app/tools/schema.py`）：

```python
from dataclasses import dataclass, field
from typing import Optional

@dataclass
class EvidenceCard:
    source_type: str          # announcement | financial_report | news | research_report | industry_data | web_search
    title: str                # 标题
    url: str                  # 原文链接（必填，用于溯源；无法取得时填数据接口说明）
    publish_time: str         # ISO8601，如 "2026-04-28T18:30:00+08:00"；未知填 ""
    source_name: str          # 如 "巨潮资讯网" / "东方财富" / "博查搜索"
    symbol: Optional[str]     # 关联股票代码，如 "300750.SZ"；行业/宏观数据可为 None
    excerpt: str              # 原文摘录或数据要点，<= 800 字
    structured: dict = field(default_factory=dict)  # 结构化字段（因 source_type 而异，见各工具定义）
    reliability: int = 3      # 可信度 1-5：官方披露=5，主流媒体/券商=4，聚合搜索=3
    fetch_tool: str = ""      # 产生本卡片的工具名，如 "fetch_announcements"
```

可信度赋值规则（写死在各工具里）：巨潮公告/交易所披露=5；财报接口数据=5；券商研报=4；财联社/东财/新浪新闻=4；博查网页搜索结果=3。

## 2. 数据源总览与选型理由

| 信息类型 | 首选数据源 | 获取方式 | 备选/降级 | 费用 |
|----------|-----------|---------|----------|------|
| 公司公告 | 巨潮资讯网（官方指定披露平台） | akshare `stock_notice_report` / `stock_zh_a_disclosure_report_cninfo` | 直连 cninfo HTTP 接口 | 免费 |
| 财报三大表 | 东方财富（akshare 封装） | `stock_profit_sheet_by_report_em` 等 | 新浪财报接口 / Tushare | 免费 |
| 财务指标 | 东方财富（akshare 封装） | `stock_financial_analysis_indicator` | Tushare `fina_indicator` | 免费 |
| 新闻资讯 | 东方财富个股新闻 + 财联社电报 | akshare `stock_news_em` / `stock_telegraph_cls` | 博查搜索限定新闻 | 免费 |
| 券商研报 | 东方财富研报中心 | akshare `stock_research_report_em` | 博查搜索 site:data.eastmoney.com | 免费 |
| 行业数据 | 东方财富行业板块 + 国家统计局宏观 | akshare 行业/宏观系列接口 | 博查搜索 | 免费 |
| 通用联网搜索 | 博查 Bocha Web Search API | HTTP POST | 智谱 web-search 工具 | ¥0.036/次 |
| 行情/估值 | 东方财富（akshare 封装） | `stock_zh_a_hist` / `stock_individual_info_em` | 新浪行情 | 免费 |

**被替代的境外工具对照**（写入比赛材料用）：Google Search → 博查 Web Search；Bing Search API（国际版）→ 博查；Zep Cloud → 自托管 Graphiti+Neo4j；境外新闻源 → 财联社/东财/新浪。

**akshare 使用注意（执行 Agent 必读）**：
1. akshare 本质是对东财/新浪/巨潮公开接口的爬虫封装，接口偶尔因目标网站改版失效。**每个工具必须做降级**：首选接口抛异常时按本文档"备选"列降级，且在 EvidenceCard.structured 里记 `degraded: true`。
2. 全局限速：同一数据源相邻两次请求间隔 >= 1 秒（新浪源 >= 3 秒），实现一个 `RateLimiter`（`backend/app/tools/rate_limiter.py`，按域名维度的令牌桶即可）。
3. 所有 akshare 调用包一层 `run_with_timeout(fn, timeout=30)` 与 3 次指数退避重试（复用 MiroFish `backend/app/utils/retry.py`）。
4. requirements 固定 `akshare>=1.18.0`，并在 README 提示部署时 `pip install -U akshare` 以获取最新接口修复。

## 3. 工具定义（逐个实现）

以下每个工具一个小节。格式：函数签名 → 实现要点 → 输出映射 → 失败降级。文件路径统一 `backend/app/tools/<模块名>.py`。

### 3.1 fetch_announcements — 公司公告（巨潮）

```python
def fetch_announcements(symbol: str, start_date: str, end_date: str,
                        category: str = "all", max_count: int = 30) -> list[EvidenceCard]:
    """获取个股公告列表。
    symbol: 6位代码，如 "300750"；category: all|年报|半年报|一季报|三季报|业绩预告|重大事项|股权变动
    """
```

实现要点：
- 首选 `ak.stock_zh_a_disclosure_report_cninfo(symbol=symbol, market="沪深京", start_date=..., end_date=...)`，返回列包含 公告标题/公告时间/公告链接。
- category 过滤用标题关键词匹配（"年度报告"、"业绩预告" 等），在 Python 侧过滤而非依赖接口参数。
- `structured` 字段：`{"category": 推断出的公告类别, "announcement_id": ...}`。
- PDF 正文获取：公告链接指向巨潮 PDF。实现辅助函数 `download_announcement_pdf(url) -> str`（下载 + `pypdf` 抽文本，>50页只取前 30 页 + 最后 5 页），供分析 Agent 的 `read_announcement` 工具按需调用，**采集阶段不默认下载全文**（控制耗时）。
- 降级：akshare 失效时直连巨潮接口 `http://www.cninfo.com.cn/new/hisAnnouncement/query`（POST 表单：stock=代码, seDate=起止日期），User-Agent 设为常见浏览器。

### 3.2 fetch_financial_statements — 财报三大表

```python
def fetch_financial_statements(symbol: str, statement: str = "income",
                               period_count: int = 8) -> list[EvidenceCard]:
    """statement: income|balance|cashflow; period_count: 最近 N 个报告期"""
```

实现要点：
- 东财接口需要带交易所前缀的代码：`SH600519` / `SZ300750`（600/601/603/605/688 开头→SH，000/001/002/003/300/301→SZ，8开头→BJ，实现 `normalize_symbol()` 放 `tools/symbol.py` 全局复用）。
- 接口映射：income→`ak.stock_profit_sheet_by_report_em`，balance→`ak.stock_balance_sheet_by_report_em`，cashflow→`ak.stock_cash_flow_sheet_by_report_em`。
- 返回的 DataFrame 列极多（100+），**不要全量塞给 LLM**。每个报告期生成一张 EvidenceCard，`structured` 只放白名单字段：
  - income: REPORT_DATE, TOTAL_OPERATE_INCOME(营业总收入), OPERATE_PROFIT(营业利润), TOTAL_PROFIT, NETPROFIT(净利润), PARENT_NETPROFIT(归母净利润), BASIC_EPS
  - balance: TOTAL_ASSETS, TOTAL_LIABILITIES, TOTAL_EQUITY, MONETARYFUNDS(货币资金), INVENTORY, ACCOUNTS_RECE
  - cashflow: NETCASH_OPERATE, NETCASH_INVEST, NETCASH_FINANCE, END_CASH
- `excerpt` 用中文模板拼出人话："2026年一季报：营业总收入 XX 亿元，同比…（同比值若接口给出则用接口值，否则自算相邻同期比）"。金额统一换算为"亿元"保留两位小数。
- 降级：新浪 `ak.stock_financial_report_sina(stock="sh600519", symbol="利润表")`。

### 3.8 web_search — 博查联网搜索（谷歌替代）

```python
def web_search(query: str, freshness: str = "oneMonth", count: int = 8,
               site: str = None) -> list[EvidenceCard]:
    """freshness: oneDay|oneWeek|oneMonth|oneYear|noLimit"""
```

- HTTP：`POST https://api.bochaai.com/v1/web-search`，Header `Authorization: Bearer {BOCHA_API_KEY}`，Body `{"query": query, "freshness": freshness, "summary": true, "count": count}`。site 非空时 query 拼 `site:xxx`。
- 响应取 `data.webPages.value[]`：name→title, url→url, summary/snippet→excerpt, siteName→source_name, datePublished→publish_time。
- **费用护栏**：单次任务运行内 web_search 调用次数上限 10 次（计数器放任务上下文），超限返回错误文本提示 Agent 改用免费数据源。
- 降级：博查余额不足/超时 → 返回空列表并在卡片流水里记 `search_unavailable`，不阻塞整体任务。

### 3.10 read_announcement — 公告全文精读（分析阶段工具）

```python
def read_announcement(url: str, question: str = None) -> str:
```

- 供分析 Agent 在 ReACT 循环中按需调用：下载 PDF → 抽文本 → 若 question 非空，用 DeepSeek `deepseek-v4-flash` 非思考模式做"带着问题读"的定向摘要（单次 LLM 调用，输入截断 30k 字符）→ 返回 <= 1500 字文本。
- 缓存：以 url 的 md5 为 key 缓存抽取文本到 `uploads/cache/announcements/`，避免重复下载。
- **多模态增强**：当 `pypdf` 抽取的文本量 < 200 字/页（判定为扫描件或图片型 PDF）时，自动降级走 §3.11 的视觉解析路径。

### 3.11 parse_pdf_visuals — 公告表格与扫描件视觉解析（多模态·输入侧）

```python
def parse_pdf_visuals(pdf_path: str, max_pages: int = 8) -> dict:
    """本地表格优先；候选扫描/图表页按需调用视觉模型。"""
```

- 本地模式：`pdfplumber` 逐页抽文本与表格；PyMuPDF 只渲染低文本密度或图片/图表候选页。全任务最多 `VISION_MAX_PAGES`（默认 8）页。
- 视觉模式：调用百炼 `qwen3-vl-plus`，按 OpenAI content array 发送 `image_url` Base64 Data URL + 文本指令；Base64 只存在请求内存，不落盘。结果保存页码、PDF SHA-256、结构化 Markdown、置信度和安全模型元数据。
- 无视觉 Key 或调用失败时保留本地结果，并返回 `visual_incomplete=true` 与“视觉证据未完整解析”；禁止把 DeepSeek Key 用于图片，也禁止把百炼作为文本静默后备。
- 这是本产品的**多模态能力落点之一**（比赛加分项）：年报中的股权结构图、扫描版募集说明书、图片型业绩发布会 PPT 均可被解析进证据体系。返回文本进入 read_announcement 的结果流，来源标注 `(视觉解析)`。
- 环境变量：`VISION_LLM_PROVIDER=dashscope`、独立 `VISION_LLM_API_KEY`、`VISION_LLM_MODEL=qwen3-vl-plus`、`VISION_MAX_PAGES=8`。缓存身份包含 PDF SHA-256、模型、能力状态和解析器版本；不缓存临时视觉失败。

- timeline 类型专供追踪简报与推演报告的演化时间线。
