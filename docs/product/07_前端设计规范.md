# 07 · 前端设计规范

> 基线：直接在 MiroFish frontend 上改造。技术栈保持不变——Vue 3.5（Composition API + `<script setup>`）、Vue Router 4、Vite 7、Axios、vue-i18n、D3 力导向图；**无 UI 组件库、无 Pinia**（沿用轻量 reactive store 模式）；异步一律 setInterval 轮询，无 WebSocket。
> 改造策略：保留 `GraphPanel.vue`（D3 图谱）、轮询工具函数、`LanguageSwitcher`、整体"左图谱右工作台"布局能力；重写路由与 Step 组件。

---

## 2. 页面规格

### 2.1 Home（新建任务）

- 需求输入 textarea + 三个示例模板 chip（摘要/对比/追踪各一，点击填入示例文案）；
- 可选上传区（pdf/md/txt，≤50MB，复用 MiroFish 上传组件与 pendingUpload store）；
- **偏好预填**：mounted 时调 `GET /api/memory/prefill`，若 watch_symbols 非空，输入框下方展示"常用标的"chip（点击追加进需求文本）；
- 提交 → `POST /api/task/create`（multipart）→ 跳 `/task/:id/confirm`；
- 下半屏：历史任务卡片列表（状态徽标、交付物类型图标、点击进对应页面）。

### 2.2 TaskConfirm（任务卡确认，新增）

- 将 task_card JSON 渲染为可编辑表单：交付物类型（radio）、标的（tag 输入，带代码校验提示）、时间窗（日期区间）、信息类型（checkbox×5）、关注点（tag 输入）；
- `clarifications` 数组渲染为黄色提示条（逐条确认）；
- 「开始研究」→ `POST /api/task/{id}/confirm`（body=当前表单）→ 跳 `/task/:id`；「返回修改需求」→ 回 Home 带回原文。

### 2.3 TaskRun（任务运行页，演示核心页）

三栏布局（沿用 MiroFish graph/split/workbench 切换能力）：

- **左栏 · 管线进度**：垂直步骤条（解析→采集→建图→分析→审校→装配），当前阶段高亮 + progress 百分比（`/status` 2s 轮询）；采集阶段展开显示 5 个采集 Agent 子行（名称、状态 spinner/✓/✗、已采卡片数，来自 progress_detail.collectors）；分析阶段展开章节列表（progress_detail.sections）。
- **中栏 · Agent 动作流水**：按 agent 分泳道（或统一时间流+彩色 agent 徽标）渲染 agent_log 增量行（`/agent-log?from_line=` 2s 轮询，复用 MiroFish Step4Report 的增量日志逻辑）；action 类型映射展示样式：tool_call=蓝色卡片（工具名+参数摘要）、tool_result=灰色折叠、react_thought=斜体、error=红色；审校 revise 事件高亮橙色（演示看点）。
- **右栏 · 证据与图谱**：上半证据计数器（5 类 source_type 各一行，数字滚动动画）；下半 GraphPanel 缩略图（15s 轮询 `/task/{id}/graph`，节点按实体类型着色：Company 蓝/Disclosure 绿/Event 红/Opinion 紫/Metric 黄）。
- status=completed → 顶部出现「查看报告」大按钮自动跳转（3s 倒计时）。

### 2.4 Report（报告页）

- 主区：渲染 full report markdown。**Markdown 渲染引入 `marked@^12` + `DOMPurify`**（替换 MiroFish 自研 renderMarkdown——报告含表格，自研版不支持）+ **`echarts@^5`**（渲染正文中的 ```chart 数据块，04§3.12：line/bar/timeline 三种图型，图表下方自动附 source_refs 角标行）；前端新增依赖仅此三项 + `github-markdown-css`；
- **角标组件**：渲染前把 `\[E(\d+)\]` 替换为 `<sup class="evidence-ref" data-id="$1">[$1]</sup>`，点击弹 Popover：标题/来源/发布时间/摘录/「查看原文」外链（evidence 数据来自报告接口 sources，建 id→card 索引）；
- 每章节尾部反馈条：👍/👎 + 评语输入（提交 `POST /api/feedback/section`，提交后显示"已记录，系统将学习你的偏好"）；报告末尾星级评分；
- 右侧对话抽屉（改造 Step5Interaction 聊天 UI）：`POST /api/report/chat`，展示回复中的 tool_calls（"查证过程"折叠区）；
- 顶部操作条：开启追踪订阅（弹窗选 daily/weekly+时间 → `POST /api/tracking/subscribe`）、**情景推演**（进入推演配置）、导出 Markdown（`/markdown` 下载）、查看审校记录（弹窗列 review_log，演示合规点）、查看完整图谱（全屏 GraphPanel）；
- "风险与关注点"章节的每个风险条目尾部渲染「推演此情景」小按钮（携带该条 evidence_id 调 `POST /api/scenario/create`）。

### 2.4b Scenario（情景推演页，10 文档配套）

单页四状态切换（按 scenario status 驱动）：
1. **配置确认**：ScenarioConfig 渲染为表单（假设文本、注入事件列表可编辑、规模/轮数滑块并实时显示预估耗时与成本"约 20 分钟 / ¥5"、双情景开关默认开且附说明）；顶部固定显示 10§7 的模拟声明横幅（琥珀底色）；
2. **运行中**：改造 MiroFish Step3——左侧双情景 Tab（悲观/基准），每 Tab 内轮次时间线 + 模拟广场消息流（角色徽标按 7 类着色）；顶部总进度与预计剩余时间；支持中途停止；
3. **报告**：同报告页渲染（S 角标样式与 E 角标区分：S 用虚线下划线，Popover 显示模拟动作/采访原文而非外链）；
4. **采访抽屉**：改造 Step5——左侧角色列表（头像+角色类型+一句话人设），点选后对话；输入框上方提示"你正在采访模拟角色，其回答仅代表沙盘内的演化状态"。

### 2.5 Tracking（追踪中心）

- 订阅列表：任务标题、cron、状态、暂停/恢复/删除、「立即重跑」；
- 选中订阅 → 右侧简报时间线（日期倒序卡片：新增 N 条/变更 M 条徽标，展开渲染简报 markdown）。

### 2.6 Profile（我的偏好，"越用越默契"可视化）

- 区块 1 偏好标签：user_preference 条目渲染为可删除 tag（DELETE 后提示"7 天内不会重新学习该偏好"）；
- 区块 2 经验规则库：playbook 表格（规则内容/来源任务/状态徽标 candidate 灰、active 绿、retired 划线/命中次数），candidate 行有「确认启用」按钮；
- 区块 3 学习效果：`/playbook/stats` 渲染两个数字对比卡（命中规则任务平均星级 vs 未命中）+ 规则数趋势；
- 区块 4 数据源健康度：`/source-health` 表格（工具名/成功率进度条/平均延迟/降级率）；
- 底部危险区：「清空全部记忆」（二次确认 → DELETE /api/memory/user）。

## 3. 公共模块

- `src/api/index.js`：按蓝图分组封装全部接口（沿用 MiroFish axios 实例与 `VITE_API_BASE_URL || http://localhost:5001`）；
- `src/composables/usePolling.js`：抽出通用轮询 hook（start/stop/间隔/终止条件），替换 MiroFish 各组件手写 setInterval（改造时顺手统一，避免泄漏定时器的老问题）；

## 4. UX 设计原则（面向真实研究员试用，执行 Agent 逐条落实）

1. **时间预期管理**：任何超过 5 秒的等待必须显示三要素——当前在做什么（人话，如"财报采集 Agent 正在读取近 8 期利润表"）、整体进度百分比、预计剩余时间（按历史 task_run 同类任务均值估算，`/status` 返回 `eta_seconds`，后端从 stage_timings 统计）。推演页尤其重要（15-25 分钟）：允许用户离开页面，顶栏通知完成（复用追踪通知通道）。
2. **空状态即引导**：首页无历史任务时展示三张"试试这个"示例卡（直接点击即发起）；追踪中心/偏好页空态说明该功能如何被触发。
3. **首次使用引导**：首个任务运行页出现一次性浮层（3 步：左边是流程、中间是 Agent 实况、右边是证据），`localStorage` 记录不再弹出。
4. **可逆与可控**：任务运行中可取消；推演可中途停止且已产生的轮次数据保留可看；所有反馈可撤销（再次点击取消）。
5. **错误的人话化**：采集降级/失败在界面上用友好文案（"新浪数据源今天有点慢，已自动改用东方财富"），技术细节收进折叠区；任务失败页给出明确下一步（重试按钮 + 修改任务卡入口）。
6. **信任设计**：证据角标、可信度盾牌、审校记录、数据完整性说明、免责声明——所有信任元素必须默认可见而非隐藏在二级菜单（这是金融工具的核心 UX）。
7. **键盘友好**：需求输入框 Cmd+Enter 提交；报告页 `[` `]` 切换章节；对话抽屉 Esc 关闭。
8. **演示模式**：`?demo=1` 查询参数下，页面隐藏危险区按钮并放大字号 10%（录屏与现场演示用）。

## 5. 视觉基调

沿用 MiroFish 现有自写 CSS 变量体系，主色改为深蓝（#1a3a6b 系，金融质感），强调色琥珀（数据高亮）；证据可信度 5/4/3 分别用实心/半实/空心盾牌小图标；所有金额右对齐等宽字体。不引入 UI 框架（保持包体与改造成本最小）。
