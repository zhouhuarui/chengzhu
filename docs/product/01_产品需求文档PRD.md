# 01 · 产品需求文档（PRD）

> 产品名：成竹（英文名 Foresketch）。命名典故：苏轼《文与可画筼筜谷偃竹记》"画竹必先得成竹于胸中"——画家落笔前，完整的竹已在心中画成；本产品在投资决策发生前，先把信息全景与情景推演"画"在数字沙盘中。英文名 Foresketch = fore（预先）+ sketch（画家草稿），呼应《黑客与画家》"黑客与画家同为通过草图迭代的创作者"的创作观。
> 赛题：4.3.3 AI+金融 · 投研信息整理 Agent —— 对公告、财报、新闻、研报和行业数据进行摘要、对比与追踪
> 本文档回答：给谁用、解决什么痛点、用户怎么用、系统交付什么、边界在哪。

---

## 1. 目标用户

| 用户画像 | 典型角色 | 使用频率 | 核心诉求 |
|----------|---------|---------|---------|
| P0 卖方/买方初级研究员 | 券商研究所助理、私募研究员 | 每天 | 把"翻公告、扒财报、追新闻"的 2-4 小时体力活压缩到 10 分钟，且**每条结论可溯源** |
| P1 上市公司对标/IR 人员 | 董秘办、战略部 | 每周 | 竞品公司披露对比、行业动态追踪 |
| P2 严肃个人投资者 | 有基本面分析习惯的个人 | 每周 | 一站式获得某标的的结构化信息全景，替代在 5 个 App 间来回切换 |

主打 P0：比赛演示以"研究员早晨接到任务：两小时内交一份宁德时代季度跟踪"为主线场景。

## 2. 场景痛点（比赛材料需逐条对应功能）

1. **信息散**：公告在巨潮、财报在东财/Wind、新闻在财联社、研报在各家 App，人工聚合耗时且易漏。→ 对应功能 F1 多源并行采集。
2. **信息厚**：一份年报 300+ 页、一个季度 40+ 条公告，通读不现实。→ F2 可溯源摘要。
3. **对比难**：跨期（本季 vs 上季 vs 去年同期）、跨公司（宁德 vs 比亚迪电池业务）的对比需要手工做表。→ F3 结构化对比。
4. **追踪断**：事件是演化的（问询函 → 回复 → 处罚），人工跟踪靠记忆和收藏夹。→ F4 时间线追踪 + 定时简报。
5. **工具不懂我**：通用 AI 工具每次从零开始，不记得"我关注锂电、我要表格不要长文、上次它把研报评级当成事实我很不满"。→ F5 历史学习与个性化（本产品差异化核心）。

## 3. 任务闭环定义（比赛要求"可演示、可验证的任务闭环"）

**闭环 A（主演示）：需求 → 报告 → 反馈 → 进化**
1. 用户输入自然语言需求 + 可选上传自有材料（内部纪要 PDF 等）；
2. 系统解析为任务卡并回显，用户确认/修改（多轮交互点 1）；
3. 多 Agent 并行采集 → 图谱构建 → 冻结证据 → 财务标准化 → direct 分析或证据辩论 → 审校 → 交付报告（全程进度与 Agent 动作实时可视）；
4. 用户阅读报告，逐章节点赞/点踩/文字评价，或在对话框追问（多轮交互点 2）；
5. 反馈写入用户记忆与经验规则库；用户第二次发起类似任务时，任务卡预填其偏好、报告风格自动调整（**演示时跑两轮同类任务展示差异**）。

**闭环 B（追踪）：订阅 → 定时重跑 → 增量简报**
1. 用户对任务卡开启追踪订阅（每日/每周）；
2. 调度器定时重跑采集，图谱做增量更新（Graphiti 时序特性：新事实使旧事实失效）；
3. 生成**只含增量与变化**的追踪简报，站内通知用户。

**闭环 C（推演）：风险点 → 情景假设 → 数字沙盘推演 → 观察报告 → 采访追问**
1. 用户从报告风险点一键发起（或自由输入）情景假设；
2. ScenarioAgent 生成锚定真实证据的双情景配置，用户确认；
3. 系统以研究图谱为种子生成 30 个市场参与者角色（机构/分析师/媒体/散户/IR 等），运行多轮舆论演化仿真；
4. 产出情景推演观察报告（舆论时间线、多空分歧图谱、传导链、双情景对比）；
5. 用户可采访模拟世界中任意角色深挖动机（多轮交互点 3）。详见 10 文档。

## 4. 功能清单（MoSCoW）

### Must（比赛 Demo 必须完成）
- F1 多源并行采集：公告/财报/新闻/研报/行业数据 5 类专家采集 Agent（数据源见 04 文档）
- F2 摘要报告：分章节、每个论断带引用角标 `[E12]` 链接到证据卡原文 URL
- F3 对比报告：跨期财务对比（含自动计算的同比/环比表格）、跨公司对比（2-3 家）
- F4 追踪：事件时间线视图 + 追踪订阅 + 增量简报
- F5 历史学习：章节级反馈（👍/👎/评语）、用户偏好记忆、经验规则库注入 Prompt、数据源健康度自适应
- F6 过程可观测：前端实时展示每个 Agent 的阶段、最终观点与工具调用流水（继承 MiroFish agent_log.jsonl 机制），不展示或持久化原始 chain-of-thought
- F7 报告对话：报告完成后可追问，对话 Agent 可调用图谱检索与数据工具
- F8 合规护栏：审校 Agent 拦截投资建议类表述；所有页面与报告带免责声明
- F15 **仿真推演**（核心亮点，10 文档）：基于研究图谱构建市场参与者数字沙盘，对用户假设情景做双情景（悲观/基准）舆论演化推演，产出情景观察报告，支持采访模拟世界中的任意角色。合规约束：产出为情景观察，禁止指向性结论
- F16 **多模态解析**（04§3.11-3.12）：输入侧——公告 PDF 表格结构化 + 扫描件/图表候选页百炼 `qwen3-vl-plus` 视觉理解；输出侧——报告内 ECharts 图表（数据 100% 溯源到证据卡）
- F17 **证据化基本面辩论**：摘要/对比任务可选 `evidence_debate`。系统以“稳健与质量”“成长与变化”两个研究视角进行固定两轮交叉质询，确定性 EvidenceAuditor 检查引用、数字和财务口径，Judge 只综合通过硬检查的观点；报告固定披露共识事实、主要反证、未决分歧、证据不足和后续公开事项。旧任务与追踪任务保持 `direct`。

### Should（时间允许则做）
- F9 用户上传自有材料（PDF/MD）注入研究图谱（复用 MiroFish 文件解析 + 图谱构建）
- F10 报告导出 Markdown/PDF
- F11 图谱可视化页（复用 MiroFish 前端图谱组件）

### Could（比赛后迭代计划里写）
- F12 多标的组合监控看板；F13 财报电话会音频转写摘要；F14 移动端适配

### Won't（明确不做，写入合规边界）
- 不做投资建议/评级/目标价；不做交易接口；不做未公开信息获取；不做个股荐股排行。
- 比赛版辩论不生成 Alpha 因子、PIT 全市场面板、IC/ICIR、代码因子、回测或股票排序；不扩展到 tracking；辩论阶段不联网补采，证据缺口只形成待补请求。

## 5. 核心交互流程（前端页面级，详见 07 文档）

```
[首页/项目列表]
   └─ 新建研究项目 → [任务创建页]
        ① 自然语言输入需求（示例引导：摘要类/对比类/追踪类各给一个模板）
        ② （可选）上传自有材料
        ③ 提交 → 系统返回任务卡 JSON 的人话版卡片 → 用户可改标的/时间窗/交付物类型
           摘要/对比任务可选“直接分析”或“多视角证据辩论” → 确认并获得 run_id
   └─ [任务运行页]（核心可视化页）
        左栏：管线阶段进度（解析→采集→建图→冻结→标准化→[辩论→裁决]→分析→审校→装配）
        中栏：Agent 动作流水 / 辩论面板（观点、反证、撤回、硬审计；不展示原始思维链）
        右栏：证据卡计数器（公告12｜财报8｜新闻20｜研报6｜行业4）
   └─ [报告页]
        run 选择器 + 章节化正文（含 ECharts 溯源图表）+ 引用角标悬浮显示证据卡
        + 每章节反馈组件 + 右侧对话/辩论记录抽屉
        顶部按钮：开启追踪订阅｜情景推演｜导出｜查看图谱
        风险条目尾部「推演此情景」→ [情景推演页]
   └─ [情景推演页]（10 文档）
        配置确认（双情景+成本预估）→ 模拟广场实况（角色分色）→ 推演观察报告 → 角色采访抽屉
   └─ [追踪中心]
        订阅列表 + 历次简报时间线
   └─ [我的偏好]（历史学习可视化，演示加分点）
        系统学到的偏好标签（可删除）、经验规则库条目、数据源健康度面板
```

## 6. 输入输出规格

**输入**：
- 自然语言需求，10-500 字；
- 可选 PDF/MD/TXT 上传（单文件 <= 50MB，沿用 MiroFish 限制）；
- 任务卡确认/修改（结构化表单）。

**输出（三种交付物，模板见 03 文档分析 Agent 节）**：
- 摘要报告：`执行摘要 / 公告要点 / 财务表现 / 市场与舆情 / 券商观点汇总（标注为观点） / 行业背景 / 风险与关注点 / 信息来源清单`
- 对比报告：`对比结论概览 / 财务指标对比表 / 业务与披露差异 / 舆情与研报观点对比 / 信息来源清单`
- 追踪简报：`本期新增（增量事实） / 变化与更正（旧事实失效） / 时间线更新 / 下期关注点`
- 证据辩论附加结构：`共识事实 / 主要反证 / 未决分歧 / 撤回观点 / 证据不足 / 假设 / 后续公开事项`；仅通过硬审计并经裁决的 Claim 可进入正文。
- 每份交付物末尾固定附：免责声明 + 数据源与时间戳说明（09 文档规定文案）。

## 7. 非功能需求

| 项 | 指标 |
|----|------|
| 任务时长 | 摘要/对比任务端到端 <= 8 分钟（采集并行度 5；辩论最多两轮、四维度） |
| 可溯源率 | 报告中事实性论断 100% 带证据角标（审校 Agent 强制检查） |
| 失败恢复 | 任一采集 Agent 失败不阻塞整体，报告中显式披露缺失项 |
| 成本 | 单次任务文本与视觉 LLM 总成本 <= ¥2，博查搜索 <= 10 次 |
| 事实口径 | 无效证据引用、未对齐财务比较、未裁决 Claim 进入正文三项均为 0 |
| 隐私 | 原文件存本地；必要文本发送 DeepSeek，候选图片页发送百炼 Qwen-VL；Base64、Prompt、Key 与原始思维链不落盘 |

## 8. 成功指标（比赛答辩用）

- 演示指标：同一需求二次运行时，任务卡预填准确、报告风格随反馈改变（前后对照截图）；
- 效率指标：人工完成同等信息聚合约 3 小时 vs 系统 8 分钟；
- 质量指标：证据角标覆盖率 100%，抽查 20 条引用无一条张冠李戴。
- 辩论指标：EvidenceAuditor 必须拒绝 H1/Q1、累计/单季、合并/母公司、币种或单位不一致的比较，Judge 不得覆盖硬失败；投资建议黑名单命中为 0。

## 9. 迭代计划（比赛材料要求）

- V1.0（比赛版）：Must 全部 + F9/F11；
- V1.1：组合监控看板、更多数据源（港股通、可转债公告）、PDF 导出；
- V2.0：财报电话会多模态摘要、团队协作空间、私有化部署包。
