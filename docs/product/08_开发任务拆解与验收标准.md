# 08 · 开发任务拆解与验收标准

> 本文档是执行 Agent 的施工顺序表。按 Phase 顺序执行，**每个任务卡完成后必须先跑验收命令再进入下一张**。
> 引用约定：任务卡中的"§"指向本文档集其他文档章节，如 `04§3.1` = 04 文档第 3.1 节。
> 工作目录：新建仓库 `chengzhu/`（不要直接改 MiroFish 目录；从 MiroFish 拷贝文件时保留其 LICENSE 声明，MiroFish 为开源项目）。

---

## Phase 0 · 骨架与基础设施（预计 0.5 天）

**T0.1 仓库初始化**
- 按 02§5 建后端目录树；从 MiroFish 拷贝：`utils/llm_client.py, openai_chat_compat.py, retry.py, logger.py, file_parser.py`、`models/task.py`、`services/text_processor.py`；前端整体拷贝 MiroFish frontend 后按 07 文档改造（本 Phase 只需能 `npm run dev` 起来）。
- 写 `config.py`（README 环境变量总表全部接入）、`constants.py`（09§2 文案）、`.env.example`、根 `package.json`（沿用 MiroFish 的 concurrently 双启动脚本）。
- 验收：`python backend/run.py` 启动无报错且 `GET /api/health` 200；前端 3000 端口可访问空壳首页。

**T0.2 Neo4j（本地原生安装，不用 Docker）**
- 本地开发统一 `brew install neo4j` 原生运行（`neo4j start`，限制堆内存：`conf/neo4j.conf` 设 `server.memory.heap.max_size=1g`、`server.memory.pagecache.size=512m`，控制资源占用）；README 写清安装与启停命令。
- `docker-compose.yml` 仍要写（backend、frontend、neo4j:5.26），但**仅作为交付评委的可选部署形态**，开发与本机演示不依赖 Docker。
- 验收：`neo4j start` 后 7474 可登录；`python -c "from neo4j import GraphDatabase; ..."` bolt 连通。

**T0.3 SQLite 层**
- `utils/db.py`：连接管理 + 06§2 全部建表 SQL（幂等 IF NOT EXISTS）+ 每表基础 CRUD 函数。
- 验收：`pytest backend/tests/test_db.py`（建表、插入、查询 task_run/feedback/playbook_rule 各一条）。

## Phase 1 · 数据工具层（预计 1.5 天，可与 Phase 2 并行）

**T1.1-T1.10 十个工具**：按 04§3 逐个实现（announcements → statements → indicators → news → telegraph → research → industry → web_search → quote → read_announcement），共享 `schema.py / rate_limiter.py / symbol.py / registry.py`。

## Phase 3 · 编排管线（预计 2 天，核心）

**T3.1 ResearchTask 状态机 + task 蓝图**：02§3.1 状态机、06§1.1 全部接口（agent-log 增量协议照抄 MiroFish report.py 实现）。
**T3.2 agent_logger.py**：移植 ReportLogger，泛化出 agent 字段（06§4.2 行格式）。
**T3.3 Planner**：03§A1。验收：pytest 用 5 条构造需求断言 TaskCard 字段（含"对比宁德和比亚迪"→compare+双 symbol；"每天盯"→tracking）。
**T3.4 采集编排器 + 5 采集 Agent**：02§3.2 + 03§A2（含默认计划兜底）。验收：对 600519 发起 summary 任务，5 个 evidence/*.jsonl 均非空，单 Agent 抛异常不影响其余，agent_log 有完整 collector 泳道记录。
**T3.5 分析 Agent**：移植 report_agent.py 骨架（解析器、ReAct 循环、大纲、装配），换 Prompt 与工具（03§A4），实现角标机制。验收：端到端跑通 summary 任务产出 full_report.md，抽查所有 [E*] 角标可映射回 evidence。
**T3.6 Reviewer + compliance_checker**：03§A5。验收：构造含"建议买入"与错误数字的章节草稿，规则层拦截前者、LLM 层标记后者，revise 流程走通且 review_log.jsonl 落盘。
**T3.7 装配 + 报告蓝图 + Chat**：06§1.2、03§A6。验收：报告接口返回完整结构；chat 追问"净利润多少"能调用图谱工具并带角标回答。
**T3.8 对比模式与追踪模式**：A4 三模式差异 + tracking 的 new/invalidated facts 查询。验收：compare 任务（600519 vs 000858）产出同口径对比表；手工二次运行 tracking 任务产出增量简报。

**T4.1 feedback 蓝图 + Reflection Agent**：03§A7、06§1.3。验收：对章节点踩并评语"只要表格"→ playbook_rule 出现 candidate 且 target_agent=analyst、rule_type=style；user_preference 更新。

## 全局验收红线（任何 Phase 违反即打回）

1. 报告中出现无角标的事实性断言 → 打回 T3.5/T3.6；
2. 出现 09§1.1 禁止表述且未被拦截 → 打回 T3.6；
3. 任何境外依赖（google/bing 国际版/zep cloud/twitter 等）进入 requirements 或代码 → 打回；
4. API Key 出现在代码或前端 → 打回；
5. 单任务成本超 ¥2、单次推演成本超 ¥8（task_run/scenario_run 有统计）→ 打回调参（降章节数/工具上限/仿真规模）。
6. 推演产出中出现无"模拟/情景/沙盘"限定语的结论句 → 打回 T8.3/T8.5。
